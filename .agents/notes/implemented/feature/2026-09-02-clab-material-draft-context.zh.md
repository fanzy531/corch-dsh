# Agent Note: CLAB 将资料暂存到原生 Conversation 草稿

Status: implemented

[English](2026-09-02-clab-material-draft-context.md) | 中文

## Problem

资料操作需要允许创作者选择多个资料并先填写处理要求，再启动模型。每份资料都通过 `session.prompt` 发送，会把选择动作变成 Conversation 轮次，也无法受控地批量提交。

## Decision

CLAB 使用现有的会话级输入门面和 `conversation.input.dock` 插槽。选择资料时，插件把可读的 Markdown 区块追加到原生文本草稿，并在作品 store 中记录资料 id。输入框上方显示待发送资料名称，并支持逐项移除。资料树支持多选，一次加入一个批次；重复选择不会重复追加区块。

原生 Composer 仍是唯一发送路径。暂存资料不会调用 `session.prompt`；用户使用 DSH 原生发送动作提交已编辑的草稿。输入状态机成功回到空闲且草稿为空后，CLAB 清除待发送 id。发送失败时保留草稿和待发送 id，用户可以修正后重试。

Conversation 中最新的 `clab-content` 节点会同步到工作台的大纲、正文和状态字段；作品标题与目标平台仍由作品总览维护，不被模型快照中的标题或平台字段覆盖。

每份资料都有预览入口。文本上传显示文件文本，图片上传显示浏览器预览，二进制上传显示转换占位说明。搜索结果保存为带有发布者和原文 URL 的 Markdown 元数据预览。

## Alternatives considered

**每份资料都直接提交 Prompt。** 这会在用户填写指令前启动处理，也无法提供一个合并的多资料上下文。

**为通用非图片 Composer 附件扩展平台。** 这能提供更原生的文件条，但需要跨包输入约定和序列化路径，轻量初版并不需要。

**只在 CLAB 自己的面板中保存待发送 id。** 如果 CLAB 不拦截发送，模型无法通过原生发送路径获得所选资料内容。把内容写入现有原生草稿可以保持单一 Conversation，并复用平台的发送、重试和草稿语义。

## Consequences

初版在不增加第二套聊天系统和平台附件约定的情况下，支持显式、批量的资料处理。暂存区块是可见且可编辑的文本，创作者可以在发送前修改或删除资料。原始二进制文件仍不进入持久化附件存储；在确定通用资料或图片引用路径前，图片资料以文字参考说明加入草稿，而不是原生图片附件。
